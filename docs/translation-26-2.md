# Java Edition 26.1 and 26.2 packet translation

Horizon uses Java Edition 26.3 resources and protocol 777. The `version-bridge` mod translates a remote connection to Java Edition 26.1 (protocol 775) or 26.2 (protocol 776). It uses the experimental `network` mod capability: a separate WebAssembly instance sees complete packet bodies after decryption and decompression, and may replace or drop them before Horizon's packet codecs run. The mod must be installed and enabled to join an older server.

Build the mod from `crates/horizon-mod-sdk/examples/version-bridge` with `cargo horizon-mod build`, then install and enable its `.hmod`. In Multiplayer, add or edit a server and set **Server Version** to **26.1** or **26.2**. The selected version is saved in `servers.dat`. For a direct launch, pass `--target-version 26.1 --server HOST:PORT` (or `26.2`). For local development, pass `--dev-mod PATH/TO/version_bridge.hmod` instead of installing it. A signed-in session is still needed for servers that require online authentication.

The server list currently sends its status ping without the mod translator. An older server may show an incompatible version or fail to show its status even when joining through the mod works.

The adapter converts the handshake, packet IDs in every connection phase, teleport acknowledgements, swings and player actions such as dropping items. In play it translates changed spawn and entity movement packets, entity metadata (including dropped item stacks), chunk light masks and block palettes, block updates, block entities, items and their component IDs, entity and particle types, sound events, explosions, recipe book entries and advancements. Numeric registry maps are generated by `tools/generate_registry_maps.py` from [ViaVersion/Mappings](https://github.com/ViaVersion/Mappings/tree/main/mappings) JSON data, whose README allows these files to be reused. The source files are not committed. The reverse diff supplies 121 fallbacks for 26.3-only item IDs when sending to 26.2; these appear as older substitute items on that server. The 26.1 mapping uses its own IDs, including the earlier brick ID and renamed spectator packet.

The 26.2 implementation has been exercised against a local vanilla server: login, chunk loading, movement, inventory updates, mobs, block entities, recipes, advancements and TNT explosions decoded, and the client completed a 10,000-frame play run without skipped packets. The 26.1 tables and packet names come from official 26.1 server reports and Via mapping data. A local vanilla 26.1 server accepted an offline login, sent 81 chunks, and kept the translated client connected for 3,600 frames without reported decode errors. This exposed two 26.1 login fields that differ from 26.2 and are now converted. The `network` API and these adapters remain experimental. Payloads not covered by these tests may still differ, especially nested item or particle data and packets from servers with plugins. Item components absent from the older version can still prevent a stack from being sent.

`horizon-protocol::connection::PacketTranslator` is the Rust interface. `horizon-client::net::Session::connect_translated`, `connect_transferred_translated` and `ping_translated` attach it to remote and status connections. The normal 26.3 path has no translator.
